# DATC — Dictionary of Abstraction Terms for Code

A git-native, database-free dictionary of abstraction terms. The data lives as
plain files under `storage/`; a small Python bridge renders it into a static,
dependency-free browser app under `web/`.

## Layout

```
storage/            # source of truth (normalized YAML "tables")
  terms/<slug>.yml     # 138 term rows: id, type, synonyms, variants, antagonists, concepts
  concepts/<slug>.yml  # 11 concept rows: id
scripts/
  validate.py       # schema + referential-integrity check (CI-ready)
  build.py          # bridge: storage/ -> web/data.js
web/
  index.html        # the app shell
  app.js            # dependency-free UI (ported from the DC design prototype)
  data.js           # GENERATED by build.py — window.DATC_DATA
reference/          # original Claude "DC" design prototype (not shipped)
```

See `storage/terms/README.md` and `storage/concepts/README.md` for the row
schemas and constraints.

## Workflow

1. Edit term/concept files under `storage/` (an edit = a PR; the repo is the DB).
2. `python3 scripts/validate.py` — fails on bad schema or dangling id links.
3. `python3 scripts/build.py` — regenerates `web/data.js` from `storage/`.
4. Open `web/index.html` in a browser. It runs straight from the filesystem
   (`file://`) — `data.js` is a plain JS object, so no server is needed.

`web/data.js` is a generated artifact committed for convenience (so the app is
runnable on clone). Always regenerate it with `build.py` after changing
`storage/`; never edit it by hand.

## Dependencies

Only Python 3 with `pyyaml` (already present in this environment) for the two
scripts. The browser app has no dependencies and no build step.
